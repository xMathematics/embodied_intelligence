# 2.1 CPU流水线与微架构

## 1. 指令流水线

### 1.1 经典5级流水线

现代CPU将一个指令的执行分解为多个阶段，每个阶段由独立的硬件单元处理：

```
┌──────┐   ┌──────┐   ┌──────┐   ┌──────┐   ┌──────┐
│ IF   │ → │ ID   │ → │ EX   │ → │ MEM  │ → │ WB   │
│取指令 │   │译码   │   │执行   │   │访存   │   │写回   │
└──────┘   └──────┘   └──────┘   └──────┘   └──────┘
  ↑PC指向     ↑解析     ↑ALU    ↑内存访问  ↑写寄存器
  指令地址    指令      计算
```

**理想情况**：每个时钟周期完成一条指令（CPI=1）。

### 1.2 流水线深度演进

| 处理器 | 流水线级数 | 频率 | 年份 |
|-------|-----------|------|------|
| MIPS R4000 | 5级 | 100 MHz | 1991 |
| Intel Pentium 4 | 31级 | 3.8 GHz | 2004 |
| Intel Core i9-13900K | 14-19级 | 5.8 GHz | 2022 |
| ARM Cortex-A78AE | 11级 | 3.0 GHz | 2022 |

**深度流水线的权衡**：
- **优点**：更高频率，更高吞吐量
- **缺点**：分支误预测代价更大（更多周期浪费）

## 2. 流水线冒险 (Pipeline Hazards)

### 2.1 数据冒险 (Data Hazard)

**问题**：后一条指令需要前一条指令的结果，但结果尚未就绪。

```asm
ADD R1, R2, R3    ; R1 = R2 + R3
SUB R4, R1, R5    ; 需要R1, 但ADD还在EX阶段
```

**解决方案**：

| 技术 | 原理 | 硬件开销 |
|------|------|---------|
| **转发 (Forwarding/Bypassing)** | 将EX阶段结果直接传给下一条指令的EX | 中等 |
| **流水线停顿 (Stall)** | 插入NOP气泡 | 无（但性能损失） |
| **编译器调度** | 编译器重排指令 | 无 |

```asm
; 编译器可以重排指令来避免冒险
; 原始：
ADD R1, R2, R3    ; 写R1
SUB R4, R1, R5    ; 读R1（需转发）
MUL R6, R7, R8    ; 与前面两指令无关

; 编译器插入无关指令：
ADD R1, R2, R3
MUL R6, R7, R8    ; 这条无关指令让转发时间更充裕
SUB R4, R1, R5
```

### 2.2 控制冒险 (Control Hazard)

**问题**：分支指令导致下一条指令地址不确定。

```asm
BEQ R1, R2, target  ; 分支指令
ADD R3, R4, R5      ; 分支后的指令（不确定是否执行）
```

**解决方案**：
- **分支预测**（详见2.3节）
- **延迟分支**：分支后的指令（延迟槽）总是执行

### 2.3 结构冒险 (Structural Hazard)

**问题**：两条指令同时需要同一硬件资源。

例如：冯·诺依曼架构中，取指令和访存都需要访问同一存储器。

**解决方案**：
- 哈佛架构（分离指令缓存和数据缓存）
- 增加硬件单元

## 3. 在机器人中的实际影响

### 3.1 控制循环中的流水线行为

```
理想流水线 (无冒险):
CC1: IF  │  (控制算法第1条指令)
CC2: ID  │ IF│
CC3: EX  │ ID│ IF│
CC4: MEM │ EX│ ID│ IF│
CC5: WB  │MEM│ EX│ ID│ IF│
CC6:     │WB │MEM│ EX│ ID│ IF│ → 6个周期完成4条指令 ✓

实际 (有数据冒险):
CC1: IF  │  (LD R1, [encoder])    -- 加载编码器值
CC2: ID  │ IF│  (计算地址)
CC3: EX  │ ID│ IF│ (地址计算)
CC4: MEM │ EX│ ID│ IF│ (内存访问, 需2个周期)
CC5: MEM2│ EX│ ID│ IF│ (继续访存)
CC6: WB  │MEM│ EX│ ID│ IF│
CC7:     │WB │STALL│ EX│ ID│  (转发解决)
→ 延迟增加了!
```

**在机器人中的表现**：如果控制循环中存在大量数据相关的指令序列（如EKF中的矩阵链式乘法），流水线效率会降低。

### 3.2 优化建议

```cpp
// ❌ 数据密集型代码（流水线效率低）
float e = a + b;       // 写e
float f = e * c;       // 读e, 写f（依赖e）
float g = f - d;       // 读f, 写g（依赖f）
// 每条指令都依赖上一条，流水线频繁停顿

// ✅ 混合无关计算（流水线效率高）
float e = a + b;       // 写e
float x = p * q;       // 无关计算（由其他传感器）
float f = e * c;       // 读e, 写f
float y = x + r;       // 无关计算
float g = f - d;       // 读f, 写g
// 无关指令填充了转发等待时间
```
