## 2. 综合案例：自主移动机器人

### 2.1 系统规格

```
平台：Jetson Orin NX 16GB
传感器：IMX219 RGB ×2 (MIPI CSI) +  LiDAR VLP-16 + BMI088 IMU
执行器：4轮差速底盘 (CAN FD)
操作系统：Ubuntu 22.04 + PREEMPT_RT + ROS2 Humble
```

### 2.2 体系结构层面的设计决策

| 决策 | 选项 | 选择 | 理由（基于体系结构知识） |
|------|------|------|------------------------|
| CPU ISA | ARM vs x86 | **ARM** | 低功耗, 集成GPU, Jetson生态 |
| 相机接口 | USB vs MIPI | **MIPI CSI** | 更低延迟 (~μs vs ms), 硬件时间戳 |
| 控制总线 | CAN vs EtherCAT | **CAN FD** | 4轮足够, 成本低, 机器人标准 |
| 存储 | eMMC vs NVMe | **NVMe (PCIe 3.0 x4)** | ~3.5GB/s, 足够记录所有传感器数据 |
| 内存 | LPDDR4 vs LPDDR5 | **LPDDR5** | 68 GB/s带宽, 满足多传感器需求 |
| 核心分配 | 默认 vs 隔离 | **核心隔离** | 控制循环需要确定性延迟 |

### 2.4 性能分析

| 阶段 | 涉及体系结构概念 | 延迟 | 优化 |
|------|----------------|------|------|
| 图像采集 | MIPI CSI DMA | <1ms | 硬件直通, 零拷贝 |
| 图像预处理 | Cache + SIMD | <3ms | Cache分块, NEON向量化 |
| YOLO推理 | GPU + 内存带宽 | 10ms | FP16 TensorRT |
| LiDAR处理 | 多核并行 | 5ms | Core2-5并行处理 |
| 传感器融合 | 缓存一致性 | 2ms | 避免伪共享 |
| 控制计算 | 核心隔离 | 0.5ms | Core0独占, 实时调度 |
| **端到端** | | **<22ms** | **满足50Hz实时性** |

## 3. 常见瓶颈与排查方法

### 3.1 性能诊断工具

```bash
# 1. 查看Cache Miss率 (perf)
perf stat -e cache-misses,cache-references ./robot_program

# 2. 查看内存带宽使用
perf stat -e mem_load_retired.l1_miss,mem_load_retired.l2_miss

# 3. 查看NUMA访问距离
numastat -p robot_pid

# 4. 查看核心使用情况
htop                          # 实时查看
mpstat -P ALL 1               # 每核统计

# 5. 查看中断分布
cat /proc/interrupts          # 中断亲和性
```

### 3.2 典型瓶颈模式

| 现象 | 可能原因 | 体系结构层面解决方案 |
|------|---------|-------------------|
| CPU利用率低但系统慢 | 内存带宽饱和 | 优化Cache利用, 减少数据搬运 |
| 控制循环偶尔抖动 | Cache Miss或TLB Miss | 热点数据对齐, 大页 |
| 多核扩展性差 | 伪共享 | 数据对齐到Cache Line |
| GPU利用率低 | PCIe带宽不足 | 检查PCIe Gen和Lane数 |
| 传感器丢帧 | 总线带宽不足 | 检查USB/MIPI带宽分配 |
